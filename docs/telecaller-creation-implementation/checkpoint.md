# A145-F01 — Dedicated paid native Telecaller creation

Primary Admin Employees now offers Add Telecaller with paid Telecaller usage/capacity guidance. The dedicated dialog retains failed input and supports name, email, optional phone/code, password/confirmation and busy/error states. It creates a Telecaller through the authenticated employee endpoint, separately from field Sales creation; the actor/company come from the authenticated principal. The shared web/native creation service checks the live primary owner inside the company-locked transaction, paid active Telecaller seats, edition and phone uniqueness. Serializable retry rechecks capacity after contention. Created users have field Sales and Account access disabled. Other admins cannot use this path. Existing web creation uses the same service and keeps its outer mutation authorization.

Non-primary dispatch is denied, and native dispatch does not call the field Sales creator. Twenty-five focused checks passed / nine optional cases skipped.
