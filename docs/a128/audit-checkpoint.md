# A128 — Payment History

Date: 12 November 2026 (Asia/Kolkata). Route: `/workspace/billing/history`. Audit only; current UI retained. No application code, order, payment, subscription, email, pricing or production record was changed.

## Existing behavior and safeguards

Web history calls loadBillingPageData/billingDashboard and inherits its billing-authority and company checks. It shows stored order amount with two decimals, currency, order status, creation time and an eight-character reference. Account-package and Plus summaries are distinct. Empty results say No orders yet. Pending orders are labelled PENDING, not claimed paid. The page renders navigation/display only, with no payment mutation form. The dashboard query is company-scoped. Native history implementation has a paged API (10 rows, createdAt/id tie-breaker, hasMoreOrders) and a Load More renderer, unlike web's fixed 50 rows; however its entry route is not reachable from the inspected native billing choices.

## Findings (OPEN)

- **A128-F01 — history entry missing from current billing navigation (Medium).** No non-test source link to `/workspace/billing/history` was found. Web Billing & Subscription exposes Subscription and Billing; Billing actions exposes only Add Sales Team, Add Account Team and Renewal. Native SubscriptionContent similarly has no transition to its history/else case; its only visible page keys are Subscription/Billing and the three actions. History code exists but ordinary users have no visible entry through these inspected flows. Provide an accessible history entry consistent with the owner's existing visual design, not a redesign. Direct authenticated web URL remains available; physical navigation was not exercised.
- **A128-F02 — older web history cannot be reached (Medium).** billingDashboard uses take:50 ordered only by createdAt descending, no offset/cursor/count. The history page has no Load More/filter/search. A synthetic 51-record fixture confirmed 50 returned records and the exact company-scoped query. Add complete, stable pagination with an ID tie-breaker and preserve tenant/authorization filters. The fixture mocked Prisma's result cap; no 51-row production or real-database probe was run. Native already has pagination and should not be regressed while correcting web.
- **A128-F03 — payment identification/details missing (Low).** billingDashboard includes payments but the page never shows manual payment reference, captured/paid date or payment detail navigation; it shows only the order's creation time and truncated order ID. A synthetic captured reference was omitted from the rendered result, while exact amount/status remained correct. Native cards similarly lack a payment transaction drill-down. Both summaries omit purchased Telecaller target information stored in order audit metadata, although Telecaller charges can contribute to totals. Expose authorized order/payment details, distinguish order creation from payment capture, and preserve exact amounts. No missing bank payment or incorrect persisted transaction was demonstrated; this is reconciliation/actionability coverage.
- **A128-F04 — native Account billing authority mismatch (Medium).** Native Account app offers Billing & Subscription and renders SubscriptionScreen, whose request uses the Sales-only mobile billing route. GET authenticates a mobile Sales principal; mobileBillingContext further requires PRIMARY_ADMIN and SALES_BILLING. An Account-only ACCOUNT_ADMIN principal is rejected with FORBIDDEN/403 by a direct service probe before any data read. Web billingUser supports Account Admin for the Account edition. Align native account-billing authentication/authority with the intended edition without exposing Sales controls or accepting caller tenant IDs. This shared native billing-gate issue also affects other billing views; cross-reference this ID in later pages rather than count duplicate root causes. No actual mobile-token request or device run was attempted.

## Related observation

Web formats creation time in the server's default timezone and native strips the ISO timestamp's suffix without a zone label. This should be reviewed under the already recorded timezone-consistency policy rather than treating an order creation time as an authoritative payment-capture time. Current audit does not certify temporal display on non-India devices/hosts.
