# First additional branch setup

A134-F04: web and native Add Branch now require an explicit first-additional-branch choice. KEEP_HEAD_OFFICE retains the existing Head Office and starts an empty named branch. MOVE_EXISTING uses the existing business/branch identity for the named branch and creates an empty primary Head Office, copying the previous Head Office contact/address/tax profile. Existing financial record IDs, branch foreign keys, stock history and staff branch-assignment IDs are retained; the business location's live name/contact metadata changes to the supplied branch details. This is an identity-preserving first split, not a rewrite of posted financial records.

The shared web/native transaction serializes by company, rechecks current Main Admin membership/workspace authority, rejects absent or stale first-transition choices and records the decision atomically. Audit failure rolls back the whole transition, including primary status. Later branches use the ordinary create flow; inactive historical branches still mean the company has already made its first split. Primary Head Office deactivation protection remains. Native uncertain saves ask the user to refresh rather than claiming failure means nothing was saved. Legacy creation clients without the required first choice receive an explicit conflict rather than an automatic decision.
