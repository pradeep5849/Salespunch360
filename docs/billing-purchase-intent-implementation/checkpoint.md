# A127-F01 — Preserve Sales/Plus renewal versus addition intent

Existing web Renewal/Add Team/Add Account paths and native equivalents now carry their purchase mode through preview, reviewed checkout and manual-order creation. The authoritative server resolves/stores purpose in the immutable creation audit. Full renewals charge every selected Sales/Account/Telecaller unit for a full term even with an active same-capacity term, and activate after existing paid terms. Explicit increased-capacity renewals remain future renewals. True additions validate current period, no reductions and the allowed dimension of growth; they charge only added capacity through the common expiry. Older clients without mode infer pure same-period growth as an addition and other selections as full renewal. Separate Account-only package flow is unchanged.

Pending order/idempotent reuse checks purpose as well as target capacity. Ambiguous historical pending intent requires explicit review/cancellation rather than silently changing price. Payment capture obeys recorded purpose, queues repeated renewals without overlap, rejects expired/changed addition terms or priced baseline capacity, and rechecks current Telecaller usage. Future Plus Account reductions wait for term start and use the existing oldest-retained lifecycle under the due-reduction transaction. Historical paid amounts are not rewritten. No schema migration.
