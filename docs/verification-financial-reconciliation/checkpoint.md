# Independent saved-record reconciliation and explicit coverage

A120-F02 now reads saved document lines/discount choices, effective payment/advance allocations, original receipt/advance totals, financial-year dates and current period-lock boundaries. It compares saved line/header totals without reapplying today's item/tax settings. Inclusive rounding, reverse charge, withholding and header charges retain their existing semantics. Effective exposure uses posted journals, corrections and retained return credits, excluding released/reversed allocations. The original balanceDue field is an entry snapshot, not a live balance cache; it is deliberately not compared with current outstanding. Original advance applications and subsequently released credit remain separate.

The scan identifies header/discount inconsistency, over-allocation, settlement/remaining-advance mismatch, dates outside the assigned year, missing full locks on closed years, and possible postings after the current lock's latest change. The last check is a review warning, not a reconstruction of historical lock versions. New nested collections are counted before loading and remain bounded at 50,000 children per relation, with the existing read-only snapshot and statement/transaction deadlines.

Independent opening/control stock and physical count completeness cannot be inferred from the same movement ledger. The scan explicitly returns NOT_CHECKED for that comparison, with manual reconciliation instructions. Bank statements and historical lock changes remain explicitly outside coverage. Existing positive-movement and paired-transfer checks remain separate. This satisfies the original finding's explicit alternative of marking unavailable comparisons as not checked; it does not claim a new independent stock-control ledger. Both verification and close-year reviews disclose the limitation without presenting zero affected records as a clean stock result. No automatic history repair is introduced.
