## Current behavior and positive checks

The page loads authorized company billing context and accepts six-month/yearly periods. It rejects a zero Manager+Sales target. ADD_TEAM review requires a current paid term, matching period, no target reduction, at least one addition and unchanged Plus Account packages. ADD_ACCOUNT review requires Plus, matching paid term and unchanged Sales/Telecaller targets. Render/service probes confirmed selected review guards. GET review itself calls no order creation. Existing tests cover company serialization, current usage and payment-time Telecaller target activation.

## New findings

- **A127-F01 — renewal intent lost; active-term same-capacity base quote can be zero (High, OPEN).** The page uses purchaseMode to select headings and review guards but omits it from quoteUnifiedSalesTeam. createOrderAction also discards purchaseMode when calling the order service. The shared request schema and quoteBillingOrder do not distinguish explicit renewal from an increment. With an active synthetic term (1 Admin, 1 Manager, 2 Sales), 100-unit role prices and the same requested capacity, the actual quoteBillingOrder returns subtotal=0.00, prorated=true and the old expiry. The same target without an active term returns 400.00. Thus an active-term renewal is calculated as zero added capacity rather than a new full term. The Telecaller component may differ, so this probe establishes a zero base quote, not that every complete checkout total is zero. Keep renewal/addition intent authoritative through review, creation and activation, with explicit term/target validation. No actual zero-priced order was paid or activated in this audit; do not claim a customer has received a free renewal.
- **A127-F02 — Telecaller surcharge attachment is separate and race-prone (Medium, OPEN).** createUnifiedSalesTeamOrder completes createBillingOrder before attachTelecallerTarget. The attachment marker is checked outside its subsequent transaction; inside, order status is read but the marker is not rechecked under an explicit lock. Two synthetic concurrent calls both observe no marker and increment the same pending order, creating two markers. BillingAuditEvent schema has no unique entity/type/reason key that would establish this marker's uniqueness. A separate failure probe shows attachment can reject after the mocked base-order operation succeeded. This is a source/mocked concurrency hazard, not a real-PostgreSQL race or actual duplicate charge demonstration. Include base order, exact target snapshot and surcharge marker/update in one correctly locked idempotent operation, or implement a resumable protocol that cannot expose an incomplete/doubly enriched pending order. Existing payment-time Telecaller activation atomicity tests do not establish order-construction atomicity.
- **A127-F03 — quote errors escape the review without local recovery (Low, OPEN).** quoteUnifiedSalesTeam is awaited without local failure handling on the page. A synthetic PRICING_UNAVAILABLE rejects the page before review can render; the generic application error boundary offers no field-specific billing explanation or retained selection. Provide safe pricing/validation/expired-term feedback and a retry path while preserving authoritative rejection. No network/provider outage was triggered.

## Shared findings, not duplicate IDs

- A125-F02 precision loss also affects final totals here: a synthetic quote of 100.50 renders ₹101 because the local money formatter uses zero fraction digits. The full value remains in the quote object; do not infer an actual changed charge from the label alone.
- A126-F02 pending-intent reuse uses the same helper for Sales orders. The existing serialization test intentionally verifies pending reuse, but it does not prove matching reviewed targets. Track the shared helper correction rather than count a second root-cause finding.
- A126-F03-style normalization is also present in this page's count helper; dedicated input handling should preserve explicit intent rather than silently altering it. No additional numbered finding is assigned solely from this source similarity.
