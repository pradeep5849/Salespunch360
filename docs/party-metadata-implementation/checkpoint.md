# A166-F02 / A167-F01 — Account customer and vendor metadata editors

Account party and vendor cards now link to scoped editors for saved contact, address, tax and notes fields. Read/write permissions use ACCOUNT_ACCOUNTS. Customer access requires isAccountCustomer and the actor's allowed branches; vendors retain their existing company-wide catalogue scope. Mutation checks the current active Account role/branch grants under company/user share locks and uses a conditional updatedAt revision to reject competing edits. Unknown fields, assignment/branch/account-flag/creation-key and balance injection are rejected. Customer billing-address edits preserve the separate visit address, Sales assignment and creation-intent metadata. Omitted fields remain unchanged, including hidden tax/shipping and untouched legacy values. Metadata and operational audit commit together; posted document snapshots and financial amounts are not edited.

The client keeps drafts on validation/network/stale failures, disables controls while saving, advances its revision only after success, and offers an explicit reload for stale data. Refreshed server props do not silently rebase a dirty draft. Editor identity is keyed to kind/record. Existing party settings govern the displayed optional fields.

Validation: 23 focused tests passed; 21 real isolated SQL cases passed, including branch denial, a single winner under competing edits, preserved tax/shipping/visit/assignment fields and rollback after an injected audit failure. All 168 migrations applied only in the owned fixture. TypeScript, changed-file lint and whitespace passed. Seven isolated Chromium checks used the actual React form with a mocked server action; browser-check.json records their scope. This is not full authenticated application/browser/device acceptance. Previous full regression: 4236 passed / 453 optional skipped; no repeat full suite claimed for this metadata slice. Final-head CI remains required.
