# A120-F03 / A120-F06 — Canonical transfers and bounded verification

Warehouse verification now follows the actual inventory writer: sourceType TRANSFER creates exactly one OUT and one IN for one product/lot. It compares positive base quantity, stored unit/total value, batch/serial identity, movement date, distinct warehouses and company warehouse branch attribution. Balanced duplicate/split/multi-product legs under one source no longer pass. Project material receipt/issue/return source types are not misclassified as missing warehouse transfer pairs. The earlier synthetic split-leg acceptance assumption was corrected against the production transfer writer; no posted rows were changed. Broader Project/base-stock/allocation reconciliation remains open under A120-F02.

Before materializing rows or nested collections, the verifier counts the scoped collections inside the caller transaction. Interactive budgets are 10,000 records per collection and 50,000 journal lines / user branch-assignment rows. A limit returns an explicit incomplete ERROR with no PASS results and no invented affected-record count. This also blocks financial-year closure until verification can complete. Large companies above these limits require a scoped financial-year review or authorized offline audit; no background/offline execution system is included here. Requests use a transaction-local eight-second statement deadline, with standalone RepeatableRead scans limited to 15 seconds and a five-second acquisition wait. Internal verification requires an explicit transaction client; close-books keeps its caller transaction. Asset-assignment validation uses indexed maps/sets rather than repeated full-array searches.

Web/native clearly distinguish incomplete scans from clean checks. Native refresh failures hide previous PASS cards, label the last response time, and do not recommend repair for a passing check. These are additional A120-F05 improvements; its actionability/drill-down finding remains partial.
